# dsh-knowledge-canvas

给 DeepSeek Harness 的树状知识库：一个你自己也能改的知识库，模型有配套工具读写它。

## 问题

**你把事情讲清楚了，下一段对话它还是不知道 —— 或者更糟，它以为知道，但那条已经过时了。**

这不是"上下文不够长"。本机这个工作区实测过一次：

```
$ node report-kb-use.mjs
50 tool call(s) in the log, 1 session(s)
  写 13 次（ops / …）
  读 1 次（read-animation）
  ⚠ 先写后读：第一次写入之前没有读过
```

**写进去 13 次，读出来 1 次** —— 而那次读的还是另一个库。也就是说：
知识**被记录**了，而**没有被用**。而"记录"这件事本身是免费的（模型顺手就写了）；
**"用"才是难的**，因为要用它就得先知道它存在、还得知道哪一条现在还算数。

所以这个插件不做"更好的记忆"，它做两件别的事：

1. **让知识变成你能直接改的文件** —— 而不是只能由模型维护、你只能旁观的东西
2. **让模型知道"什么时候该来看"** —— 每个节点最后一行写清它的适用时机（见下）

## 它在解决什么

这个插件把知识放进**文件**里，而文件你可以直接改：

```
<工作区>/.dsh-knowledge/<库名>.json     一个库就是一棵树
```

- **面板在右侧**：一棵树画在画布上，能平移缩放，能拖节点、连线、改正文
- **模型有工具**：能读、能写、能挂关联，改动带 `[新增]` `[修改]` `[已废弃]` 标记，等你审
- **每个会话能单独选**用哪几个库，不用改全局设置

## 功能

| | |
|---|---|
| 画布 | 节点按父子关系画成树，可平移缩放；节点可拖动，位置会记住 |
| 节点 | 标题 + 正文（markdown）；宽度按内容自适应，也能手动调 |
| 连线 | 右键节点拖到另一个节点，给两个节点挂一条关联 |
| 搜索 | 按标题或正文找；命中后画布定位过去 |
| 定位 | 按节点 id 定位（对话里提到 `o14` 时，能直接在画布上找到它） |
| 注入 | 默认只给大纲（标题 + 触发行）；每个库可以单独选**整库全文** |
| 修改标记 | 模型改过的节点带标记，你审完可以清掉 |

## 触发行：每个节点最后一行

节点正文的**最后一行**写成：

```
什么时候该想起它：<什么情况下这个节点适用>
```

那一行会被抽出来放进系统提示的大纲里，所以模型知道**什么时候该来看这个节点**，
而不是把整篇正文塞进上下文。这是这个插件和省上下文之间最主要的那个约定。

## 装

**npm**（推荐）：包名 `dsh-knowledge-canvas`，在 DSH 的「添加插件」里填它。

**第一次运行会放一个教程库。** 如果这个工作区还没有 `.dsh-knowledge/`，插件会建一个，
里面是 `welcome.json` —— 六个节点：这个库是什么、怎么读、怎么改、值得写什么，
以及一条写对了的笔记长什么样。它是打开状态，所以模型也会读到。
它就是一个普通的库，随时可以删。（把整个 `.dsh-knowledge/` 目录删掉就能拿回默认；
只有在那个目录不存在时才会重新生成。）

**从源码**：

```json
// profiles/desktop/package.json
"dependencies": { "dsh-knowledge-tree": "link:<仓库路径>" },
"dsh": { "profile": { "bundles": [ ..., "dsh-knowledge-tree" ] } }
```

> 从源码 link 时用的名字是这个包**自己的** `package.json` 里的 `name`。
> 发布的包叫 `dsh-knowledge-canvas`（`dsh-knowledge-tree` 在 npm 上已被别人占用），
> 而本机那个目录里的 `name` 仍是 `dsh-knowledge-tree` —— 它同时是 `link:` 的目标名。

## 模型用的工具

```
knowledge_read            读一个库（或者列出所有库）
knowledge_create_base     新建一个库
knowledge_write_node      新建 / 改一个节点
knowledge_link            给两个节点挂关联
knowledge_remove_node     废掉一个节点（保留记录，不是删除）
knowledge_select          开关一个库（对当前会话，或对全局默认）
knowledge_remove_base     把一个库移出（移到 .removed/，可恢复）
```

**关掉一个库 = 模型不能读它也不能写它** —— 不是"只是不进提示词"。
（面板里仍然可以编辑：那是你在改，走的是另一条路。）

## 开发

```sh
npm run check:all      # 9 条检查 + 313 项断言
```

改 `index.js` / `lib/*` 后**必须重启 Harness**（宿主那一半在进程启动时加载一次）；
改 `client.js` 后刷新页面即可。
