# dsh-knowledge-canvas

给 DeepSeek Harness 的知识库：模型**靠判断去取，而不是靠相似度**。

## 问题

**你把一件事讲清楚了，下一段对话它还是不知道 —— 或者更糟，它以为知道，而那条已经过时了。**

这不是上下文长度的问题。在一个工作区里实测过：

```
$ node report-kb-use.mjs
50 tool call(s) in the log, 1 session(s)
  写 13 次（ops / …）
  读 1 次（read-animation）
  ⚠ 先写后读：第一次写入之前没有读过
```

**写进去 13 次，读出来 1 次** —— 而那次读的还是另一个库。知识**被记录**了，而**没有被用**。记录是免费的：模型顺手就写了。用才是难的 —— 要用它，得先知道它存在，还得知道哪一条现在还算数。

## 它哪里不一样

这不是"带搜索框的笔记应用"。四个决定，其余都是它们的推论。

### 一、触发器行，而不是向量索引

每个节点正文的**最后一行**写它什么时候适用：

```
什么时候该想起它：<这个节点适用的情形>
```

**只有那一行**进系统提示。于是：

- **没有嵌入、没有向量库、没有相似度阈值。** 检索是模型在判断，而它判断的依据是一句人写的话
- **一个节点能不能被找到，取决于写它的人有没有说清"什么时候"。** 这就是全部的赌注：知识库难的不是存，是**被查阅**；而被查阅是写法的性质
- **没写的节点会被标出来。** 索引里显示 `（无触发器）`，而写工具在你写下的那一刻就告诉你 —— 因为一个全是找不到的节点的库，看起来和一个健康的库一模一样

### 二、索引是一棵树，不是一堆片段

父子关系本身是信息 ——"这条属于那个主题"。索引按层级展开，所以模型读到的是一套结构，而不是一把碎片。一个全是平级的库也是好库；而一个什么都不挂在任何东西下面的库，通常是失误。

### 三、审核标记在每一种模式下都保留

模型做的每处改动带 `[新增]` / `[修改]` / `[已废弃]`，直到你审过。**全文注入时也保留** —— 而那正是最容易丢的地方，也确实丢过：一个测试会话发现它分不出哪些段落还没被审。

### 四、它会告诉你到底有没有用

`report-kb-use.mjs` 读插件的 `activity.log`，回答：这个会话里读了几次、写了几次、以及第一次写入之前有没有读过。上面"问题"里那个数字就是这么来的 —— 也是这个插件不声称任何它没量过的东西的原因。

## 机制

| | |
|---|---|
| **触发器行** | 正文最后一行，会被抽进索引。缺了由上面的 lint 标出 |
| **新鲜度** | 每个库的标题带节点数和最新时间戳，而每次写入都报自己那条的时间戳 —— 于是"我刚写的还没进索引"是可判定的，不用猜（猜错的代价是重写一遍） |
| **两种注入** | 默认给索引；每个库可以单独选**全文**。是每个库自己决定，不是全局开关 |
| **作用域** | 一个会话用哪些库：工作区默认，或仅本会话的覆盖 |
| **关掉就是关掉** | 关掉一个库 = 模型既不能读它也不能写它，不是"只是不进提示词" |
| **普通文件** | 一个库是 `<工作区>/.dsh-knowledge/` 下的一个 JSON。能 grep、能 diff、能提交、能拷走 |
| **自带教程** | 一个工作区第一次运行时创建一个六节点的库讲上面这些，且是打开状态。随时可删 |

## 面板

右侧画布：节点按树排布，可平移缩放，拖动移位，右键拖出关联，每个节点可改颜色和宽高。能按标题或正文搜索，也能按 id 定位 —— 所以对话里提到 `o14` 时，你能在屏幕上指出它。

## 装

**npm**（推荐）：包名 `dsh-knowledge-canvas`，在 DSH 的「添加插件」里填它。

**从源码**：

```json
// profiles/desktop/package.json
"dependencies": { "dsh-knowledge-tree": "link:<仓库路径>" },
"dsh": { "profile": { "bundles": [ ..., "dsh-knowledge-tree" ] } }
```

> 从源码 link 时用的名字是这个包**自己的** `package.json` 里的 `name`。
> 发布的包叫 `dsh-knowledge-canvas`（`dsh-knowledge-tree` 在 npm 上已被别人占用），
> 而本机那个目录里的 `name` 仍是 `dsh-knowledge-tree`。

## 模型用的工具

```
knowledge_read            读一个库（或者列出所有库）
knowledge_create_base     新建一个库
knowledge_write_node      新建 / 改一个节点
knowledge_link            给两个节点挂关联
knowledge_remove_node     废掉一个节点（保留在文件里，带标记）
knowledge_select          开关一个库（对当前会话，或对全局默认）
knowledge_remove_base     把一个库移出（移到 .removed/，可恢复）
```

## 开发

```sh
npm run check:all      # 9 条检查 + 326 项断言
```

改 `index.js` / `lib/*` 后**必须重启 Harness**（宿主那一半在进程启动时加载一次）；
改 `client.js` 后刷新页面即可。
